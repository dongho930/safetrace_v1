# 콘솔 판단 출처와 검토 사유 표시

규칙이 판단을 덮어쓸 때 기록에 저장된 `1.00`은 모델 확률이 아니다. 콘솔은 판단 출처를 확인해 모델 의견과 규칙 결과를 구분한다. 저장된 조사 결과·확률·서명 기록·담당자 판정은 바꾸지 않는다.

## 표시 기준

- 규칙 결과는 대표 숫자를 숨기고 `규칙 판단`·규칙 사유를 보여 준다. 출처와 수치가 있는 원래 모델 의견은 별도 줄에 보존한다.
- 모델과 Safe Browsing 위험 평판이 충돌한 사건은 요약·목록·경로 지도의 숫자와 대안 분포를 숨기고 충돌 사유를 표시한다. 행동 기록의 원래 모델 의견은 유지한다.
- 일반 모델 의견은 기존 숫자를 유지한다. 숫자 앞에 `AI 판단값` 문구는 붙이지 않는다. 요약의 판단 출처는 별도 칩으로 표시한다.
- 검토 사유는 모델 불확실성·규칙·평판 충돌·회선 차단 추정·무응답·판단 서비스 실패를 구분한다. 연관 조사 중에도 원래 조사의 `main_reason`을 사용한다.
- 담당자가 위협 또는 정상으로 확정하면 현재 검토 요청을 숨긴다. 원래 모델의 보류 의견을 강한 확정 문구로 바꾸지는 않는다. 담당자 보류는 검토 요청을 유지한다.
- 출처가 불명확하거나 유형이 `unknown`이거나 확률이 누락·비정상인 값은 숫자로 표시하지 않는다. 실제 `0`은 `0.00`으로 유지한다. 연관 후보 출처는 현재 결과와 일치하는 마지막 하위 조사 기록으로 확인한다.

## 후속 수정 (2026-10-28, `fix/decision-display-followup`)

#111 뒤에 콘솔의 확률·판정 문구를 다시 검토해 남은 것을 고쳤다. 저장된 판단·서명 기록·서버 상태와 사유는 바꾸지 않는다.

- **Safe Browsing 일치를 서버 사유가 아니라 평판 결과로 본다.** AI 가 이미 보류한 사건은 서버(`runner.py` 는 COMPLETED 일 때만 사유를 `reputation_match` 로 바꾼다)가 사유를 `agent_finished`·`low_confidence_action` 으로 두어, #111 의 평판 충돌 처리가 걸리지 않았다. 이런 사건은 요약 제목이 '위험 근거를 찾지 못했습니다'인데 바로 아래 카드는 빨간 'Safe Browsing 일치'였다. 이제 `reputationHit` 이 일치 주소를 신고·경유 주소와 연관 후보로 가르고(서버 `only_cands` 와 같은 기준), 조사 판단이 정상인데 이 사건의 주소가 일치하면 제목이 'Safe Browsing 위험 일치 · AI 는 위험 근거를 찾지 못했습니다'가 되고 숫자를 숨긴다. 검토 줄 맨 앞에도 평판 일치를 적는다(위협·판단 불가 의견이면 'Safe Browsing 위험 일치', 후보만 일치면 '연관 후보의 Safe Browsing 위험 일치'). 요약의 검토 줄은 제목과 겹치는 충돌 문구를 빼고, 목록 줄은 그대로 둔다.
- **코드 규칙이 정한 유형을 'AI' 로 부르지 않는다.** 판정 막대는 모델이 고른 유형만 '(AI 추천)'으로 미리 고르고, 규칙이 정한 유형은 '(규칙 판단 유형)'으로 적되 미리 고르지 않는다(링크 정지·단축 경고·사칭 도메인은 내용을 못 본 채 피싱으로 두기도 한다). 연결된 사건 줄은 서버가 판단 기록에서 정한 출처(`source`: model·rule·null)로 'AI 피싱'·'규칙 판단 피싱'·'피싱'. 현황판은 숫자가 AI 와 코드 규칙을 합친 것이라(호스팅·브랜드 통계의 '위협 사건'에 규칙 판단도 들어가야 한다) 이름표를 '조사 판단(AI·코드 규칙)'으로 바꿨다.
