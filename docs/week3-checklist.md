## 5. 3주차에 찾아 고친 것

- **검증한 체인과 내보내는 체인이 다름(High, #45)**: 패키지·보고서가 체인을 검증할 때와 내용을 만들 때 따로 읽어, 그 사이 에이전트가 체인을 바꾸면 '검증 통과 + 바뀐 의견'이 나왔다. 1주차 패키지에도 있던 문제다. 체인·증거 파일을 한 번 읽어 그 내용으로 검증하고 내보낸다.
- **ZIP 서명이 보고서를 덮지 않음, 서명된 기록의 자료형 미검사(#45)**: 서명을 SHA256SUMS 까지 넓히고, 기록 종류별 자료형을 맞춰 어긋난 필드는 `integrity.malformed` 에 적는다.
- **무한 스크립트로 워커 멈춤(A03, #46)**: 사건 하나가 10분 넘게 '조사 중'에 멈추고 대기열 전체가 막혔다. 탐색 전체 강제 기한(예산 + 15초)과 정리 작업 제한을 뒀다.
- **시험 도구 자체의 허점(#46)**: 조사 대상 페이지가 시험 서버의 금지 도달 기록을 지울 수 있었고, 공격 페이지에 접속하지 못한 사건도 '차단'으로 셀 수 있었다. 둘 다 막았다.

이번 최종 점검에서 제품의 새 실패는 없었다. 점검 도구(`tools/live_check.py`)에서 Codex 가 두 가지를 찾아 고쳤다: 받은 쪽 검증이 ZIP 에서 **빠진** 증거 파일을 건너뛰던 것, 공격 시험이 중간에 죽거나 일부만 끝나도 통과로 세던 것(`attack_suite.py` 도 하나라도 실패하면 종료 코드 1), '관리자 역할 자동화 토큰' 항목에 다른 역할 토큰을 쓸 수 있던 것(이제 역할별로 고르고, 관리자 토큰이 없으면 미검증으로 실패. 이 PC 의 `.env` 에는 관리자 토큰만 있어 앞선 결과도 관리자 토큰으로 확인한 것이었다). 둘 다 고치기 전 코드에서 실패하는 시험(`tests/test_live_check.py`)으로 확인했다.

## 7. 점검 뒤 보탠 것: 접속 주소별 로그인 제한, 접수 한도 (10/13)

6절에 남았던 두 보안 과제를 처리했다(`feat/ip-login-and-intake-limits`).

- **접속 주소별 로그인 제한**(`backend/safetrace/ratelimit.py`): 한 주소의 실패가 15분 안에 30회에 닿으면 창이 끝날 때까지 그 주소의 로그인을 **비밀번호 확인 없이** 429(`Retry-After`)로 거절한다. 아이디를 바꿔 가는 스프레이와 Argon2id 계산 부하를 막는다. 계정별 5회 잠금은 그대로다. 시도마다 먼저 한 칸을 잡고 성공하면 돌려주므로, 동시에 몰아 보내도 한도를 넘지 못하고 성공이 이전 실패를 지우지 않는다. 처음 막힐 때 감사 로그 `auth.ip_limited`, 실패 기록(`auth.login_failed`)에 `ip=` 를 붙였다. 콘솔 로그인 화면은 '로그인 시도가 너무 많습니다. N분 뒤…'를 보여 준다.
- **접속 주소를 믿는 범위**: nginx 가 `X-Forwarded-For` 를 접속 주소(`$remote_addr`)로 **덮어쓰고**, API 는 `ST_TRUSTED_PROXIES=["web"]` 로 찾은 web 컨테이너에서 온 요청만 그 머리글을 쓴다. 다른 컨테이너(예: 서명망에 같이 있는 에이전트)가 직접 보낸 값은 무시한다. uvicorn 의 `--proxy-headers` 는 127.0.0.1 을 기본으로 믿어 컨테이너 안에서 주소를 위조할 수 있었으므로 `--no-proxy-headers` 로 바꿨다(점검 도구가 찾음).
- **접수 한도**: 끝나지 않은(`QUEUED`·`RUNNING`) 사건이 주체(계정·자동화 토큰)별 20건이면 429, 전체 200건이면 503. 세기와 넣기 사이를 잠가 동시에 보내도 넘지 않는다. 같은 멱등 키 재시도는 한도와 무관하게 같은 사건을 돌려준다. 거절은 감사 로그 `case.rejected`. 처음에는 'TERMINAL 이 아닌 상태'를 셌는데, 로컬 DB 에 상태 전이 검사 전에 남은 `DONE` 사건이 있어 한 칸을 영영 차지했다(점검 도구가 찾음). 대기·조사 중만 명시해 센다.
- 설정: `ST_LOGIN_IP_MAX_FAILED`(30)·`ST_LOGIN_IP_WINDOW_S`(900)·`ST_TRUSTED_PROXIES`·`ST_CASE_MAX_PENDING_PER_PRINCIPAL`(20)·`ST_CASE_MAX_PENDING_TOTAL`(200). 제한 수는 API 프로세스 메모리에 둔다(프로세스 하나, 재시작하면 비워짐, 주소 1만 개 상한).
